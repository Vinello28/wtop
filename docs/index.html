➤ wtop

A resource monitor for Windows with the aesthetic and visual density of btop — designed to have a literally minimal footprint on the system it's watching.

Monitored subsystems

CPU

Global utilization with a high-density braille history graph, plus up to 128 per-core load bars on a green → amber → coral gradient. Model read straight from CPUID.

MEMORY

Used, available and total physical RAM, commit limit / commit charge, and a dedicated history graph.

DISK

Mounted volumes with free/total space and real-time read/write throughput via high-performance counters.

GPU

3D/Compute engine utilization (WDDM DirectX), allocated dedicated VRAM, and the graphics adapter name.

NETWORK

Real-time download/upload throughput via the native IP Helper interface table, plus total session traffic and the active adapter name.

PROCESSES

Sortable by CPU%, RSS memory, PID or name, with instant search/filter and process termination.

Under the hood
  • Sub-pixel braille graphics — Braille Unicode (U+2800–U+28FF) gives a 2×4 sub-pixel resolution per cell, for curves as smooth and dense as btop's.
  • Zero-WMI architecture — no WmiPrvSE.exe, no COM serialization. Every metric comes from direct Win32 / NTDLL calls: NtQuerySystemInformation, GlobalMemoryStatusEx, GetIfTable2, native PDH.
  • Isolated collector thread — a dedicated worker samples hardware and hands immutable snapshots to the render thread, so the UI never blocks and redraws at 60 FPS.
  • Dual 24-bit TrueColor themes — dark charcoal with neon accents, or an alabaster light theme for bright rooms. Toggle instantly with t, saved to config.
  • Dynamic sampling rate — adjust the refresh interval live with + / -, from 250ms up to 5000ms, to trade responsiveness for even lower overhead.

Build from source 
git clone https://github.com/Vinello28/wtop.git
cd wtop
cargo build --release
.\target\release\wtop.exe

User configuration (theme, sampling rate, sort order) is saved automatically to %APPDATA%\wtop\config.json.
